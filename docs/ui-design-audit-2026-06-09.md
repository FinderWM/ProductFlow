## 总体判断

产品已经具备完整的工作台型页面骨架，核心问题集中在全局层级、品牌占位、暗色主题、移动端密度与页面视觉系统缺少统一约束。当前最需要优先处理的是移动端标题重叠、固定品牌层穿透抽屉、全局暗色覆盖策略和 Gallery 页面视觉断裂。

建议把这轮优化拆成两个层次：

1. 处理会影响可用性的布局与层级问题。
2. 收敛视觉系统，沉淀页面模板和组件规范。

## 新增产品需求：布局方案可配置切换

当前 UI 设计需要保留，不能被新方案直接替换。本轮审查探索出的新布局也需要保留，最终产品应支持两套 UI 布局方案并行存在，并在设置页允许用户切换。

建议定义两套方案：

- `classic`：现有 UI 布局方案，作为默认值，保证当前用户工作流和视觉习惯不被破坏。
- `workspace`：本审查文档提出的新设计方案，可调整页面布局、导航结构、信息架构、组件形态和视觉系统，收敛品牌、层级、移动端操作区、Gallery 媒体库和 Analytics 页面模式。

配置入口建议放在 `/settings`：

- 设置项名称：`UI 布局方案`。
- 控件形态：segmented control 或 radio group，选项为 `经典布局` 与 `工作台布局`。
- 生效范围：优先按当前用户保存；团队统一场景可扩展为全局默认值和用户覆盖值。
- 生效方式：切换后立即预览或刷新当前页面生效，设置页需要明确提示当前方案。
- 兼容策略：未配置、读取失败或权限不足时回退到 `classic`。

实现约束：

- 不用新方案覆盖旧方案；旧方案和新方案都要有明确路由外壳或布局分支。
- `classic` 保留当前布局和 UI；`workspace` 可以重排页面模块、调整面板关系、替换组件样式、重新组织移动端交互和视觉密度。
- 两套方案共享数据、权限、API、表单校验和业务状态；差异集中在布局呈现、导航结构、信息层级、组件形态、视觉样式和响应式组织。
- 组件层面优先抽取共用业务组件，避免两套方案复制业务逻辑。
- 所有页面验收都需要分别覆盖 `classic` 和 `workspace`。

方案补充约束：

- 默认 URL 保持不变，优先由应用外壳和页面布局组件根据 `uiLayoutScheme` 分支，不为用户态切换新增成套 `/workspace/*` 路由。
- `classic` 只接收 P0 可用性修复、明确 bug 修复和必要可访问性修复；视觉、信息架构和移动交互密度调整放入 `workspace`。
- 设置入口建议归入体验或外观偏好；如果新增独立 section，设置页覆盖数量会从当前 12 个 section 增加，需要同步更新帮助文档和验收矩阵。
- 前端运行态可复用 `PreferencesProvider` 的语言/主题偏好模式暴露 `uiLayoutScheme`；持久化优先按用户维度保存，未接入后端用户偏好前可用本地存储作为回退。
- `workspace` 可分页面渐进接入，但未接入页面必须显式回退到 `classic`，避免同一路由出现半套新布局。

## P0：可用性与层级问题

1. 移动端创建灵感页标题区与全局品牌重叠

   - 现象：`/inspirations/new` 移动端顶部同时出现全局品牌、页面图标、页面标题和移动端 eyebrow，第一屏信息互相挤压，品牌与页面标题关系不清。
   - 证据：创建页头部从 `web/src/pages/InspirationCreatePage.tsx:762` 开始，`web/src/pages/InspirationCreatePage.tsx:770` 又在移动端重复渲染 `Inspiration One`；全局品牌在 `web/src/App.tsx:153` 无条件对认证态页面渲染。
   - 方案：把品牌从页面内容流里解耦为系统导航的一部分，移动端只保留一个品牌入口。对创建页、编辑类全屏页使用明确的 `app-shell` 顶部安全区，页面标题下移到固定导航以下。
   - 验收：375px 宽度下，品牌、返回/关闭、页面标题、描述不重叠；首屏纵向滚动前可识别当前页面和主要操作。

2. 全局 z-index 缺少分层协议，品牌会穿透抽屉

   - 现象：`GlobalBrandMark` 使用 `z-[70]`，部分抽屉和模态只使用 `z-50`，品牌可浮在弹层之上。
   - 证据：`web/src/components/TopNav.tsx:991` 使用 `z-[70]`；设置页抽屉遮罩在 `web/src/pages/SettingsPage.tsx:2331` 使用 `z-50`。
   - 方案：定义全局 layer token，例如 `nav=30`、`stickyAction=40`、`drawerOverlay=60`、`drawer=70`、`modalOverlay=80`、`modal=90`、`toast=100`。所有 `z-*` 和任意值 z-index 回收到这个协议。
   - 验收：设置页抽屉、Image Chat 移动抽屉、预览弹窗、通知层都能完整遮盖背景品牌与导航；键盘焦点只停留在当前弹层内。

3. 移动端 Image Chat 操作区占屏过高

   - 现象：`/image-chat` 移动端底部同时存在生成 CTA、快捷工具条和安全区 padding，主画布可视区域被明显压缩。
   - 证据：主容器底部 padding 在 `web/src/pages/ImageChatPage.tsx:2075`，右侧操作面板的底部 CTA 在 `web/src/pages/ImageChatPage.tsx:2416`，移动快捷工具条在 `web/src/pages/ImageChatPage.tsx:2569`。
   - 方案：移动端改为单一底部操作栏，默认只露出主操作和两个图标按钮；高级设置、历史、会话分别进入抽屉。生成中状态使用同一栏位内的进度反馈，避免额外消息条顶开布局。
   - 验收：375px 宽度下主画布高度不低于视口的 55%；选图、下载、历史、生成四类操作都可在两步内触达。

## P1：系统一致性问题

1. 暗色主题依赖全局覆盖 Tailwind 类

   - 现象：全局 CSS 直接改写 `.bg-white`、`.bg-slate-50` 等 utility 类，长期会导致局部组件和第三方组件不可预期变色。
   - 证据：`web/src/index.css:103` 至 `web/src/index.css:145`。
   - 方案：迁移到语义 token，例如 `surface-primary`、`surface-muted`、`border-subtle`、`text-primary`。页面和组件只使用语义类或设计系统组件，不再通过全局覆盖 Tailwind 原子类补暗色。
   - 验收：删除 `.bg-white` 类覆盖后，主要页面暗色模式不退化；新增组件无需依赖全局 CSS hack。

2. Gallery 视觉系统和工作台系统断裂

   - 现象：`/gallery` 使用米色 hero、强海报式标题、黑色 feed 和 fixed 品牌导航，和其他工作台页面差异过大。移动端滚动后品牌对比度不稳定。
   - 证据：Gallery 浅色 hero 在 `web/src/pages/GalleryPage.tsx:148`，硬编码渐变在 `web/src/pages/GalleryPage.tsx:155`，空状态背景在 `web/src/pages/GalleryPage.tsx:244`。
   - 方案：保留 Gallery 的媒体沉浸感，但收敛到产品的工作台外壳。桌面端使用顶部筛选栏加瀑布流；移动端首屏减少巨型标题，改为紧凑标题、资源组筛选、网格内容。黑色 feed 如保留，需要与顶部 hero 建立连续背景和导航反色规则。
   - 验收：桌面端和移动端都能在第一屏看到可操作筛选和至少一行内容；品牌、导航和图片流的背景对比稳定。

3. Image Chat 缩略图使用 `object-cover`，存在裁剪语义风险

   - 现象：会话封面、历史分支、参考图都裁剪图片。对图像生成工作流来说，裁掉边缘会影响用户判断构图和差异。
   - 证据：历史分支 `web/src/pages/image-chat/HistoryBranchStrip.tsx:206`，会话列表 `web/src/pages/image-chat/ImageChatSessionList.tsx:155`，参考图 `web/src/pages/image-chat/ReferencePanels.tsx:96`。
   - 方案：区分“封面”和“审图缩略图”。会话列表可继续 cover；历史、参考图、候选图默认 contain，并用中性底色或棋盘底纹处理留白。
   - 验收：用户能在历史和参考选择中看到完整画面边界；封面类缩略图仍保持列表整齐。

4. 页面模板重复，分析类页面可以沉淀统一模式

   - 现象：`/status` 和 `/usage-stats` 在信息架构上接近，都是指标、表格、刷新与时间维度。当前可以抽取统一 Analytics 页面模式。
   - 方案：统一为标题栏、时间范围、刷新状态、关键指标、明细表、错误/空状态六段。数字使用 tabular nums 或等宽数字，刷新与加载状态使用 skeleton，不使用独立大 spinner。
   - 验收：两个页面的过滤、刷新、错误、空数据体验一致；指标列宽和数字对齐稳定。

5. 移动端顶部控制热区过密

   - 现象：移动端遍历时多次触发天气、语言、主题相关弹层，说明顶部固定品牌、天气入口和导航控制的触发区域过密，容易和页面内容操作互相干扰。
   - 证据：全局品牌在 `web/src/App.tsx:153` 认证态无条件渲染，导航菜单和移动端更多入口集中在 `web/src/components/TopNav.tsx:103` 至 `web/src/components/TopNav.tsx:175` 与 `web/src/components/TopNav.tsx:1434` 起。
   - 方案：移动端顶部只保留品牌/当前页面/必要系统入口，天气、语言、主题放入一个明确的系统设置 sheet；页面级操作不能与全局设置入口共享同一热区。
   - 验收：375px 宽度下，滚动、打开 drawer、切换底部导航时不会误触天气或语言主题弹层；弹层打开后背景导航不可继续触发。

## P2：页面级优化建议

1. `/login`

   - 当前移动端可用，建议强化品牌首屏信号和表单错误态。输入区保持紧凑，避免再引入大幅营销文案。
   - 增加键盘焦点顺序检查，登录失败信息放在表单内部，不使用全局 toast 作为唯一反馈。

2. `/inspirations`

   - 列表页适合作为工作台基准页。建议统一列表、筛选、资源组选择、空状态和批量操作的密度规则。
   - 移动端将二级筛选收纳为水平滚动 chips 或抽屉，避免标题区高度随筛选项增长。

3. `/inspirations/new`

   - 除 P0 顶部重叠外，建议把“配置、预览、提交”按任务流分成固定区域。桌面端保持左右分栏；移动端用步骤式折叠面板，底部只保留提交与返回。
   - 错误信息目前在移动端头部下方出现，建议贴近触发区域或汇总为表单内校验列表。

4. `/inspirations/:inspirationId`

   - 详情页应强化“从灵感到生成资产”的主路径。建议把基础信息、生成记录、图片预览、进入 Image Chat 的操作做成连续工作流。
   - 图片预览弹窗与 Gallery 预览应共享同一预览组件和键盘操作规范。

5. `/image-chat` 与 `/inspirations/:inspirationId/image-chat`

   - 桌面端三栏结构明确，但左右栏在视觉重量上偏重。建议用可折叠 rail 代替完整侧栏，默认突出中间画布。
   - 移动端会话抽屉宽度为 `w-[min(86vw,360px)]`，历史抽屉固定 `w-[7.75rem]`，两者密度差异大。建议历史抽屉改为底部 sheet 或 40vw 以上宽度，支持完整缩略图与分支标签。
   - 移动端操作 sheet 内容过长，基础设置、高级设置、历史和生成操作需要分层，避免一次展开后形成超长控制面板。
   - 生成 CTA 当前暗色态使用紫/粉渐变，和产品其余页面的克制工作台风格不一致。建议收敛为单一主色，保留明确 disabled、pending、blocked 状态。

6. `/gallery`

   - 建议定位为“媒体库工作台”，减少独立海报页风格。顶部保留简洁标题、筛选、资源组；内容区使用 masonry 或稳定网格。
   - 图片预览弹窗应提供上一张、下一张、下载、来源、资源组、敏感图遮罩状态。移动端预览需要避免底部内容被浏览器安全区遮挡。

7. `/workflow/templates`

   - 个人模板页空状态偏重，建议将空状态改为较轻的 inline panel，并直接提供“新建模板”和“从系统模板复制”两个入口。
   - 模板管理页还包含复制到全局模板、审核通过/拒绝、删除确认等条件态弹窗，后续实现双布局验收时需要纳入 `classic` 与 `workspace` 的状态覆盖。
   - 模板列表建议增加状态标签、最近使用时间、可见范围，减少进入详情才能判断的成本。

8. `/settings`

   - 设置页 12 个章节均已切换，桌面端信息密度高，移动端章节选择器可用但长表单跳转成本仍高。建议左侧为设置域，右侧为表单区；移动端使用顶部 segmented control 或页面内目录。
   - 增加 `UI 布局方案` 设置项，允许用户在 `经典布局` 与 `工作台布局` 之间切换。该设置应放在通用偏好或外观设置中，切换后影响所有已覆盖页面。
   - 抽屉层级需按 P0 修复。抽屉内长表单建议使用固定底部保存栏，错误提示贴近字段。

9. `/settings/global-templates`

   - 全局模板与个人模板共用模式，但需要更强的权限和影响范围提示。移动端实测出现“模板数据加载失败”后仍显示分类与空模板列表，错误状态和空状态需要拆开表达。
   - 错误红条视觉过重，建议改为 inline alert，并在危险操作旁明确影响范围。
   - 空状态应说明当前权限和可操作动作，不只提示没有数据。

10. `/rbac`

   - 用户表格可用，但角色授权编辑器密度过高。建议拆成“角色列表、能力矩阵、成员预览”三段，编辑状态使用局部 drawer。
   - 权限矩阵需要固定首列和顶部表头，能力文案用短标签加 tooltip，避免横向滚动时失去上下文。

11. `/status`

   - 建议和 `/usage-stats` 共用 Analytics 页面结构。状态页重点显示服务健康、队列、存储、外部依赖，异常项置顶。
   - 刷新时间和请求失败状态需要显性呈现，避免用户误把旧状态当成实时状态。

12. `/usage-stats`

   - 指标页建议统一数字宽度、时间范围选择和导出入口。表格空状态要说明当前筛选条件，避免泛化无数据。
   - 移动端优先展示核心指标卡和最近趋势，明细表进入横向滚动容器或详情页。

13. `/help`

   - 三栏文档布局稳定，可作为密集阅读页参考。建议增加当前章节高亮、移动端目录 sheet 和搜索入口。
   - 帮助页可以保留比工作台更强的文本密度，但标题层级、段落宽度和代码/命令块需要统一。

## 全局修改路线

### 阶段 1：可用性修复

- 建立 z-index layer token，替换任意值 z-index。
- 修复移动端全局品牌与页面标题的占位冲突。
- 收敛 Image Chat 移动端底部操作栏，保证主画布可视区域。
- 对所有 drawer、modal、preview 做焦点、遮罩和返回焦点检查。
- 保留现有 `classic` 方案行为，新增 `workspace` 方案的布局分支不影响默认体验。

### 阶段 2：设计系统收敛

- 引入语义化 surface/text/border/action token，移除全局 Tailwind 类暗色覆盖。
- 统一工作台页面壳：顶部导航、品牌位、页面标题、主操作、内容容器宽度。
- `workspace` 方案允许页面级布局和 UI 组件重构；`classic` 方案只做必要缺陷修复。
- 统一空、错、加载、禁用、提交中状态；loading 优先使用 skeleton。
- 统一图片预览、缩略图策略和敏感图遮罩策略。
- 在设置页落地 `UI 布局方案` 偏好，并将当前方案传入应用外壳与页面布局组件。

### 阶段 3：页面体验升级

- Gallery 改为媒体库工作台，保留视觉辨识度但回到统一导航和筛选模型。
- Image Chat 桌面端把侧栏弱化为可折叠 rail，移动端把历史与设置调整为更清晰的 sheet。
- Status 和 Usage Stats 合并为一套 Analytics 模板。
- RBAC 权限编辑器从高密表单拆成矩阵和局部编辑。

## 验收清单

- 桌面端宽度：1440px、1280px、1024px。
- 移动端宽度：390px、375px、360px。
- 覆盖亮色与暗色模式。
- 覆盖 `classic` 与 `workspace` 两套 UI 布局方案。
- 设置页可以切换 UI 布局方案；未配置或读取失败时回退到 `classic`。
- 覆盖加载、空数据、错误、禁用、提交中、权限不足状态。
- 抽屉和模态打开后，背景品牌与导航不可穿透。
- 键盘 Tab 顺序可预测，Escape 可关闭弹层，关闭后焦点回到触发按钮。
- 移动端页面无横向滚动，按钮文字不溢出，底部操作不遮挡核心内容。
- 图片选择、历史缩略图、参考图能看清完整构图。
- Gallery、详情页、Image Chat 的图片预览操作一致。
